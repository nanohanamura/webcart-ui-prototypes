# Webカート カテゴリーUI 3案比較設計

## 目的

店長確認で判明した「カテゴリーを変えるたびに開き直すのが面倒」「スマホではカテゴリー画面が全面を覆い、別ページに移動したように見える」という問題を比較検討する。現行購入フローや公開試作は変更せず、実カテゴリー55件と実商品621件を使うローカル比較試作を3案作る。

## 確認できた現状

- 現行試作のカテゴリーUIは内部的には右から開くパネルである。
- スマホではパネル幅が100%のため、利用者にはカテゴリー専用ページのように見える。
- 商品分類データには親カテゴリーを示す専用項目がなく、55分類は平面的に保存されている。
- 分類名の先頭にある `●`、`◎`、`○`、`◇`、`☆` は、大分類候補として試作内で利用できる。

## 試作内だけで使う大分類

| 大分類 | 対象 |
|---|---|
| 野菜・果物 | `●` で始まる分類 |
| 冷蔵食品 | `◎` で始まる分類 |
| 調味料・主食・飲料 | `○` で始まる分類 |
| お菓子 | `◇` で始まる分類 |
| 日用品 | `☆` で始まる分類 |
| ペットフード | 分類コード90 |
| その他 | 上記以外。分類名未登録を含む |

この大分類は比較用の表示変換であり、DB、NILE、CSV、既存分類コードを変更しない。

## 共通要件

- 現在の菜の花村トンマナ、検索欄、実商品、スマホ2列商品カードを維持する。
- カテゴリー選択はページ遷移せず、同一画面で商品を切り替える。
- 選択中の大分類・小分類を文字と選択状態で示す。
- タップ領域は44px以上とする。
- 390px、768px、1024px、1440pxで横スクロールを発生させない。
- パネルやシートを閉じた後、商品一覧へ戻りやすくする。
- 比較試作から注文、ログイン、DB、NILE、CSV、メール、外部送信へ接続しない。

## A案：幅を抑えた右サイドパネル＋大分類アコーディオン

- スマホは画面幅の88%、iPad・PCは最大430pxのパネルを右から表示する。
- 背後の商品一覧を一部見せ、別ページへ移動していないことを伝える。
- 大分類を縦に並べ、開いた大分類の小分類だけを表示する。
- 選択後はパネルを閉じ、同じ商品一覧上で結果を更新する。
- 現行構造からの変更量が最も小さく、本番移植候補として推奨する。

## B案：大分類を商品一覧に常設＋小分類をコンパクト表示

- 検索欄の下に大分類を横スクロール可能なチップとして常設する。
- 大分類を選ぶと、その直下に小分類を2列で表示する。
- 小分類を選んだ後も大分類チップは残るため、別の大分類へ1操作で移動できる。
- パネルを開く回数を最も減らせるが、商品が見え始める位置はA案より少し下がる。

## C案：2列サイドパネル

- スマホは画面幅の94%、iPad・PCは最大620pxの右パネルを表示する。
- 左列に大分類、右列に選択中大分類の小分類を表示する。
- 大分類と小分類を同時に見せ、分類間を素早く比較できる。
- iPadでは最も見やすいが、390pxでは文字量が多くなるため列幅と文字サイズを慎重に調整する。

## 比較トップ

比較トップからA・B・Cを別々に開けるようにし、各案の特徴、向いている利用場面、注意点を短く表示する。各案は同じデータ、商品カード、色、余白を使い、カテゴリー操作だけを比較できるようにする。

## 検証

- 55分類が重複・欠落なく大分類へ割り当てられる。
- ペットフード4商品を含む実商品が分類選択に連動する。
- 3案とも「すべての商品」へ戻せる。
- 390px、768px、1024px、1440pxでカテゴリー操作と商品表示が収まる。
- A・Cはパネル外を押す、閉じるボタン、Escapeで閉じられる。
- キーボードフォーカス、選択状態、`aria-expanded`、`aria-selected` を確認する。
