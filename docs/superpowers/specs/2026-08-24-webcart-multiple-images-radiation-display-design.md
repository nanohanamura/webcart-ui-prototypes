# Webカート複数画像・放射性セシウム非表示 設計

更新日: 2026-08-24

## 1. 今回の境界

- 本番Webカート、NILE、本番DB、`Net_shohin.csv` は変更しない。
- `MT_SHOHIN.GAZOFILENM` は代表画像として残す。
- 商品一覧は代表画像1枚だけを表示する。
- 追加画像は商品詳細だけで表示する。
- 放射性セシウム等の公開表示は廃止するが、既存DB列・CSV列は削除しない。

## 2. 確認できた現行仕様

### 商品画像

- `MT_SHOHIN.GAZOFILENM` が現行の1商品1画像を保持する。
- 商品管理画面は画像1件を `../img/` に保存し、120×140の `_small.jpg` を生成する。
- 商品詳細も `GAZOFILENM` 1件だけを参照する。
- `30030BAT_DelImage.php` は `../img/` 直下を走査し、`MT_KAISHA`、`MT_SHOHIN`、`MT_ANNAI` の参照がない画像を削除する。追加画像を同じ直下へ置くと誤削除される。
- 本番はMySQL 5.1系で、InnoDBは利用できない。既存の画像関連追加テーブルは `MT_GAZO_*` 命名、MyISAM、UTF-8で設計されている。

### 放射性セシウム表示

- NILEの商品情報に `放射能` 項目がある。
- NILEのWeb商品生成処理が記号値を、検出限界5/10/20ベクレルまたは検査対象地域外の文章へ変換する。
- 文章は既存16列の `Net_shohin.csv` に、詳細説明・規格説明として出力される。
- Web側の取込は列数16を必須とし、列9を `SHOSAISETSUMEI`、列10を `KIKAKUSETSUMEI`、列11を `GAZOFILENM` に保存する。
- Web側に放射能専用のDB列は確認できず、公開表示・検索は説明文に混ざった文字列を利用していた。
- 取得済み公開スナップショットでは346項目に廃止対象の文言があった。
- `CS` はNILE資料内で別用途にも使われており、放射性セシウムの確定略称とは判断できない。

## 3. 推奨データ構造

第一候補はWebカート側の別テーブル `MT_GAZO_SHOHIN` とする。代表画像はこのテーブルへ移さない。

| 項目 | 型の案 | 用途 |
|---|---|---|
| `GAZO_ID` | `INT UNSIGNED AUTO_INCREMENT` | 追加画像の内部ID、主キー |
| `SHOHINCD` | `VARCHAR(20)` | `MT_SHOHIN.SHOHINCD` とアプリ側で照合 |
| `GAZOFILENM` | `VARCHAR(255)` | 追加画像ファイル名 |
| `HYOJIJUN` | `INT UNSIGNED` | 商品内の表示順 |
| `KOKAIFLG` | `TINYINT UNSIGNED` | 0:非公開、1:公開 |
| `DELFLG` | `TINYINT UNSIGNED` | 0:有効、2:削除済み |
| `ALTTEXT` | `VARCHAR(255)` | 画像の代替テキスト |
| `INSACCOUNT` | `VARCHAR(64)` | 登録した管理者 |
| `UPDACCOUNT` | `VARCHAR(64)` | 更新した管理者 |
| `INSDT` | `DATETIME` | 登録日時 |
| `UPDDT` | `DATETIME` | 更新日時 |

- エンジン: MyISAM
- 文字コード: UTF-8、`utf8_general_ci`
- 索引: `(SHOHINCD, KOKAIFLG, DELFLG, HYOJIJUN)`、`GAZOFILENM` は一意
- MySQL 5.1で外部キーを使えないため、商品存在確認・重複確認・並び順整合はPHP側で行う。
- `MT_SHOHIN` は別文字コードのため、SQL JOINせず、商品コードを正規化してPHP側で結合する。

## 4. ファイル設計

- 保存先: `/webcart/img/additional/`
- サムネイル: `/webcart/img/additional/thum/`
- ファイル名案: `P{商品コード}_{年月日時分秒}_{6桁乱数}.JPG`
- 表示順はファイル名に埋め込まずDBで管理する。
- 許可形式: JPEG、PNG、WebPは現行PHP/GD対応を実機確認してから採否決定。初期導入はJPEG/PNGを安全側とする。
- MIME実体、拡張子、画像デコード、縦横サイズ、容量上限をすべて検査する。
- 同名時の上書きは禁止し、衝突時は再採番する。

## 5. 管理画面設計

商品編集内に「代表画像」と「追加画像」を分離して表示する。

1. 代表画像: 現行 `GAZOFILENM` を閲覧のみ、既存変更操作は維持。
2. 追加画像: 複数選択アップロード、アップロード前プレビュー、代替テキスト入力。
3. 並び順: 上下ボタンまたはドラッグ操作。キーボードでも順序変更可能にする。
4. 公開状態: 画像ごとの公開・非公開。
5. 削除: 即時物理削除せず削除予定にし、保存時に論理削除。
6. 検査: 形式、MIME、容量、縦横サイズ、破損、重複ファイルを表示する。

更新は商品コード単位で排他し、ファイル保存成功後にDBを更新する。途中失敗時は新規ファイルを隔離し、既存画像と順序を維持する。

## 6. 商品詳細UI

- 1枚目は代表画像、2枚目以降は公開中の追加画像を表示する。
- メイン領域は横方向のスワイプとスクロールスナップに対応する。
- 画像下にサムネイルと `現在 / 全件` を表示する。
- サムネイルは44px以上、選択状態を枠と `aria-current` で示す。
- 画像は安定した縦長領域で `object-fit: contain` とし、読み込み時のレイアウトずれを防ぐ。
- 画像が1枚だけ、または追加画像取得失敗時はサムネイル、位置表示、スワイプ案内を出さない。
- 商品一覧カードにはカルーセルを追加しない。

試作では商品コード23だけに、本番写真ではない2枚の表示確認画像を追加して操作を確認する。

## 7. 削除処理

- 追加画像を現行 `../img/` 直下へ保存してはいけない。既存未参照画像削除処理が `MT_GAZO_SHOHIN` を参照しないため誤削除する。
- `img/additional/` は現行バッチの非再帰走査外なので、NILE・既存バッチを変えず隔離できる。
- 商品削除時は追加画像を非公開・論理削除にし、すぐ物理削除しない。
- 物理削除は専用処理で、DB未参照、猶予期間経過、バックアップまたは隔離済みを確認して行う。
- 商品が同じ商品コードで再掲載される可能性があるため、再利用か完全削除かは管理者が判断できるようにする。

## 8. 放射性セシウム表示廃止

### Web側だけで実施できる範囲

- 公開スナップショット生成時に、`SHOSAISETSUMEI` と `KIKAKUSETSUMEI` から廃止対象の定型文を除外する。
- 商品一覧、詳細、検索、カート、確認画面では除外後の値だけを利用する。
- 画面描画時にも同じ除外処理を行い、古いスナップショット混入時の再表示を防ぐ。
- 既存16列CSVはそのまま受信・保存できる。

### 今回変更しない範囲

- NILEの `放射能` 入力項目と文章生成。
- `Net_shohin.csv` の列9・10および16列契約。
- `MT_SHOHIN.SHOSAISETSUMEI`、`KIKAKUSETSUMEI` の保存値。
- 本番管理画面・本番DB。

将来、保存自体を廃止する場合はNILE出力、既存データ、CSV互換性、他利用先を含む別移行が必要である。現段階では表示だけを止める方式が最小で安全である。
