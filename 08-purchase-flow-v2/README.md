# 菜の花村Webカート 購入フロー試作08

一般発送の新規客を含め、顧客の入口と購入手続きを確認するための隔離された静的プロトタイプです。

## 確認できる経路

1. 登録済みの一般発送利用者
   - ご利用確認
   - Web会員ログイン
   - 登録済み一般発送情報
   - 注文確認
   - 操作完了
2. 登録済みの定期配達利用者
   - ご利用確認
   - Web会員ログイン
   - 登録済み定期配達情報
   - 注文確認
   - 操作完了
3. 一般発送を初めて利用する方
   - ご利用確認
   - 注文者情報入力
   - 一般発送のお届け情報
   - 注文確認
   - 操作完了
4. 新しく定期配達を始めたい方
   - ご利用確認
   - 電話相談の流れ

定期配達中の方は、店舗側でWeb会員登録も行う運用を前提に、登録済み利用者として扱います。一般発送を初めて利用する方は、店舗への電話を求めず注文者情報へ進みます。新しく定期配達を始めたい方だけを電話相談へ案内します。

## 試作内のテスト切替

ログイン画面には、登録済み情報が「一般発送」の場合と「定期配達」の場合を比較するテスト切替があります。本番ではログイン後の登録情報から自動判定する想定で、利用者へ選ばせる機能ではありません。

## 既存処理との関係

- 商品一覧は既存試作の合成商品データと53カテゴリーを使用します。
- `gc_cd`と`word`は、カテゴリーと検索条件の試作用URLパラメータとして維持します。
- 商品カードには、本番で保護が必要なhidden項目名との対応を`data-contract-fields`として記録しています。
- 一般発送用のお届け区分コードと正式名称は未確認のため、試作内で捏造していません。
- 利用者向けには「一般発送」と表示し、実装時に既存の`MT_OTODOKE`値へ対応させる前提です。

## 接続しないもの

この試作は、以下へ一切接続しません。

- 本番PHP
- Web会員DB
- 商品DB
- NILE
- 注文CSV
- 会員CSV
- メール送信
- 本番ログイン
- 本番カート
- 注文登録・注文送信
- 電話発信

入力内容とカート状態は、試作専用キー`nanohana-purchase-flow-v2`でブラウザの`localStorage`にだけ保存します。実在する顧客情報、会員CD、注文、認証情報は使用しません。

## デザインの扱い

今回は顧客分岐と購入フローの確認が中心です。文字崩れ、ボタン階層、色の競合、レスポンシブ表示は修正しますが、ブランドカラー、書体、写真、装飾を含む最終ビジュアルデザインは別工程です。
